# AdUltraPlus 独立实现项目

目标：在 `ashun520/loon-rules` 内建立独立维护的多 APP 去广告规则集，尽量保留原始 AdUltraPlus 的覆盖范围，同时消除对原维护者仓库、脚本托管和配置服务的运行时依赖。

## 实施原则

- 不把“换 Raw 链接”当成完成；逐一追踪脚本内部依赖。
- 优先重新实现行为明确的规则与响应处理逻辑，避免在没有明确再发布许可时整份搬运第三方代码。
- 不建立没有必要的动态 API。Loon 的响应改写脚本通常在客户端执行；静态配置可由本仓库托管。只有确实需要动态计算、状态或数据存储时，才评估自建 API。
- 不以拦截数量为目标；保留登录、播放、图片、搜索、内容推荐等正常业务。
- 每个模块记录来源、许可、审计结果、依赖、测试状态和回滚方式。
- 未经真实 Loon/目标 APP 测试的模块必须标注“待实测”。

## 当前状态

- 原始插件入口已读取：`https://yfamilys.com/plugin/adultraplus.plugin`
- 原始文件共 2758 行，属于综合规则集，含 URL Rewrite、响应体脚本等多种规则。
- 远程脚本不是单一来源；已发现 ddgksf2013/Scripts、fmz200/wool_scripts、zirawell/R-Store、app2smile/rules、blackmatrix7 Gist，以及一个 Cloudflare Workers 地址。
- 已提交第一阶段可安装插件 `AdUltraPlus.plugin`：包含扩展后的 URL Rewrite 规则集，以及叮咚买菜、起点读书、知乎三个本地响应体脚本模块（5 条 Script 触发规则）；仍是阶段版本，不等同于原插件完整 2758 行功能；批量导入时按规则行去重，并排除了已识别的混合业务/会员权益接口。
- 当前规则已写入本仓库，不引用原作者脚本、Worker、API 或远程配置；图标沿用原插件公开使用的启动页广告图标，并已验证图像地址可访问。
- 叮咚买菜脚本保留 GPL-3.0-or-later 来源声明；起点读书脚本保留 MIT 来源声明；知乎开屏脚本为独立实现，不复制原作者代码。三个脚本均已放入本仓库，插件触发规则已改为本仓库 Raw 地址。
- 规则与脚本尚未在真实 Loon 设备及目标 APP 上逐项实测；阶段版本需视为测试版。

## 阶段

1. 完整提取规则与远程依赖清单。
2. 对每个 JS 检查数据访问、网络请求、动态执行、混淆、持久化和外部配置。
3. 核实各来源许可证；无明确许可时采用独立重写，不直接复制再发布。
4. 将独立实现的 JS、静态配置和图标放入本仓库。
5. 生成指向本仓库 Raw 的 Loon 插件。
6. 回读检查所有脚本引用、外部域名、图标和语法。
7. 在真实设备与 APP 版本上逐模块验证，记录功能与误伤情况。

## 重要限制

GitHub Raw 可托管文本文件，但不是动态 API 运行环境。若未来需要 API 服务，必须单独选择由仓库所有者控制的部署平台，并明确其可用性、费用、密钥管理与数据流。不能把第三方 API 仍在运行称为“完全脱离第三方”。
